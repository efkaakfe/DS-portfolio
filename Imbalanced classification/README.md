# Imbalanced Classification

This project analyzes and predicts customer responses to a vehicle insurance offer (`Response`: 0 or 1). The dataset is imbalanced, so the main evaluation metric is **recall**: the model's ability to identify customers who are interested in the offer.

## Notebook

`Imbalanced classification.ipynb` documents the experiment, including exploratory data analysis, metric selection, feature preparation, baseline models (Dummy Classifier, CatBoost, LightGBM, and MLP), optimization, and evaluation on the test set. It explores three ways to handle class imbalance: SMOTE-NC (`sampling`), class weights (`weights`), and probability threshold tuning (`prob`).

## Project structure

- `data/train.csv` — training data, including the `Response` column.
- `data/test.csv` — data for inference; it may include `Response` if you also want to calculate recall.
- `data/aug_train.csv` — an additional data file.
- `scripts/train.py` — trains CatBoost, LightGBM, and MLP, compares their recall on a validation split, and saves the best model's artifacts.
- `scripts/inference.py` — loads a configuration and model artifacts, then generates predictions.
- `modules/` — preprocessing, Optuna optimization, and the MLP implementation.
- `artifacts/` — saved models, preprocessors, and inference configurations.
- `inference/` — `predictions.csv` files generated by inference.

## Requirements and environment setup

Project has been created using python `3.13.0`. Install all dependent packages using `requirements.txt` to run scripts.

```
python -m pip install -r requirements.txt
```

## Training

Run commands from the project's root directory. Training settings are in `config.json`. The current configuration uses `prob` and `5` Optuna trials:

```json
{"method": "prob", "trials": 5}
```

*   `method` can be `sampling`, `weights`, or `prob`; `None` selects baseline models without optimization
*   `trials` sets the number of optimization trials for each model

Start training with:

```bash
python -m scripts.train
```

Training compares three model types on a random train/validation split and selects the best one by recall. Optimization may take a while because the configured number of trials is run separately for CatBoost, LightGBM, and MLP. Results and artifacts are saved under `artifacts/<method>/`, including `config_inference_<method>.json`.

## Inference

By default, inference reads `data/test.csv` and `artifacts/prob/config_inference_prob.json`. Run it with the defaults using:

```bash
python -m scripts.inference
```

Pass a different configuration and/or input file with `--config` and `--data`:

```bash
python -m scripts.inference --config artifacts/weights/config_inference_weights.json --data data/test.csv
```

The output is saved to `inference/<method>/predictions.csv`. It contains a `prediction` column. If the input CSV has a `Response` column, the output also contains `true_label`, and the script displays the recall score.
